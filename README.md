# Server Hub — обзор

MCP-сервер, который даёт агенту доступ к инфраструктуре: статусы, метрики,
Docker, команды, файлы по SFTP, стриминг видео с серверов.

Приватный репозиторий: `Chegolin123/server-hub` — доступ по запросу.

## Задача

Три машины в разных сетях (VPS, домашний сервер, рабочая станция) и агент,
которому нужно отвечать «что с сервером» без ручного SSH. Вместо копипаста
команд — 21 типизированный инструмент и аудит каждого вызова.

## Инструменты

| Домен | Что |
|---|---|
| Статус | список серверов, online/offline, метрики (load, RAM, диск), health-check URL |
| Docker | список контейнеров, логи, перезапуск |
| Команды | `run_command` с denylist опасных операций |
| Файлы | SFTP: список, скачать, загрузить, удалить |
| Видео | поиск, метаданные через ffprobe, ссылка на стрим/превью/HLS |
| Отчёты | markdown-снапшот для базы знаний |

## Архитектура

```
агент (MCP stdio)
      │
      ▼
  FastMCP-сервер
      ├── config: реестр серверов (ключи, без паролей)
      ├── ssh: пул соединений asyncssh, retry при флейках sshd
      ├── monitor: метрики, docker ps/logs, health
      ├── exec: denylist + подтверждение деструктивных операций
      ├── files: SFTP
      ├── video: ffprobe, Range-стриминг, ffmpeg → HLS
      └── audit: JSONL-лог всех действий
```

Отдельный процесс `serve` отдаёт веб-страницу со стримингом и `/api/status`.

## Честная модель угроз

`run_command` — это **RCE по дизайну**: агент с SSH-ключом может выполнить на
сервере что угодно. Denylist — защита от опечаток, а не от злоумышленника:
обход кавычками, `$VAR` и `eval` тривиален.

Поэтому:

- никаких паролей в конфиге — только ключи;
- деструктивные операции требуют явного `confirm=True`;
- SSRF-фильтр отсекает приватные адреса, loopback и cloud-метадату в
  `download_url` и `health_check`;
- known_hosts проверяется, подмена host key не пройдёт;
- каждое действие пишется в аудит.

## Что не публикуется

Реестр серверов, ключи, адреса, конфиги конкретных машин.

## Почему код закрыт

Внутри — рабочие конфиги, ключи, персональные данные и коммерческая часть.
Публиковать это нельзя, поэтому открыт только обзор: что делает система,
какие решения внутри и чему она научила.
